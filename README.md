# grok-station

grok-station is a voice station you keep at home. It runs on a Raspberry Pi, listens for "Hey Grok", and shows the answer on its own screen. You set it up from a phone or laptop on your home network. The setup walkthrough is [docs/getting-started.pdf](docs/getting-started.pdf).

## What you need

- A Raspberry Pi 4 with 2 GB of memory or more. A Pi 5 is the one to get. A Pi 3B is only for a small test.
- A display plugged into the Pi, from 800x480 up to 4K (3840x2160). See **Screens** below.
- Any USB speaker and microphone, or a combined USB speakerphone.
- A microSD card, 16 GB or larger.
- A power supply for the Pi.
- 64-bit Raspberry Pi OS Lite (Trixie).
- An xAI API key.

### Screens

The station draws straight to the Pi's screen, in landscape. Sizes from 800x480 to 3840x2160 fill the whole screen, and the layout scales to fit. Bigger screens get a centered 3840x2160 picture with black borders. Smaller ones still work, but things may not fit. The automated tests check layouts at 800x480, 1024x600, 1280x720, 1280x800, 1920x1080, 2560x1706 and 3840x2160. Not every size has been tried on a real screen. Portrait (rotated) screens are untested. Touch isn't used, so a touchscreen works as a plain screen. Small status icons in the top-right corner show the network, whether Grok can be reached, the microphone, and an update arrow only while a newer version is cached. The admin home has a Grok line: Online, No internet, Can't reach Grok, or Checking. Details are in [docs/display.md](docs/display.md).

## Put it on the Pi

In Raspberry Pi Imager, choose **Raspberry Pi OS Lite (64-bit)**. Set a hostname, Wi-Fi (or use Ethernet), and SSH. Write the card, boot the Pi, and sign in.

Then run:

```bash
wget -qO- https://raw.githubusercontent.com/bwilliam79/grok-station/main/bootstrap.sh | sudo sh
```

That checks the system, downloads grok-station, and runs `install.sh`. It does not ask questions. If you already have the files:

```bash
git clone https://github.com/bwilliam79/grok-station && cd grok-station && sudo ./install.sh
```

When a fresh install finishes, it asks you to press Enter to reboot. After that, the screen shows where to open the admin page and a short code. The full install, update, and fix-it notes are in [docs/operations.md](docs/operations.md).


### Or build a ready-to-boot card

`tools/build-image/build-image.sh` makes a card that needs **no network on the Pi**: boot it, join the station's setup hotspot, and set up Wi-Fi there. It runs this repository's own `install.sh` inside the image at build time (packages, Python, wake models), and the rest of `install.sh` offline on first boot, so it is the same install as `bootstrap.sh`. Updates come through the Updates page as usual. Full details and the per-OS steps: [docs/sd-image.md](docs/sd-image.md).

1. Push the commit you want. On Linux: `sudo apt-get install -y git curl xz-utils python3 e2fsprogs qemu-user-static binfmt-support`, then `sudo tools/build-image/build-image.sh --output "$HOME/grok-station.img"`. The image builds on Linux only (a Linux PC or a Linux VM you already have); no Lima, WSL or Docker.
2. Write the image with Raspberry Pi Imager (**Use custom**), balenaEtcher or `dd`.
3. Put in the card, connect the display and the USB speaker and microphone, and power on. No cable is needed.
4. The Pi expands the card and restarts, then shows "Getting Grok Station ready" and restarts again.
5. The screen shows the setup hotspot. Join it from a phone, open the address shown, set up Wi-Fi, and finish setup.

## First steps

1. **Wi-Fi.** If the Pi is not on a network, the screen shows a setup hotspot: a Wi-Fi name, a password, and a page to open. Join that Wi-Fi, open the page, and join your home Wi-Fi. The hotspot then turns off, and the page moves to your home network.
2. **Sign in.** Open the address on the screen (`https://<hostname>.local`, or the address with the IP). The certificate is self-signed, so the browser warns you; continue past that. Enter the code from the screen, then choose an admin password. There is no username.
3. **xAI key.** Paste your xAI API key and save it. The page will not show the key again. Voice starts once it is saved.
4. **Add your main bot first.** A computer on your home network must be running the Grok Bot app, and be on and reachable 24/7, for replies to reach the station.

## Releasing

No push to `main` unless `sh tools/release-check.sh` prints `release-check: PASS` on the exact commit being pushed. The clone's pre-push hook enforces it: run `sh tools/install-release-hook` once in the release clone, and every `git push` then runs pii-guard and the leak scan (the global hooks dispatcher) and then `tools/release-check-pre-push`. That hook gates only a push whose remote ref is `refs/heads/main`: the pushed commit must be the checked-out commit and `tools/release-check.sh` must end with `release-check: PASS`, and deleting `main` is refused. Every other ref passes (pull request branches, new branches, deletes of other branches, tags), also from a checkout too old to have the hook body; in a push of several refs the `main` line decides. After a release that changes `tools/install-release-hook`, run it again once from a checkout of the new `main`. This relies on the dispatcher passing the local hook's exit status back to git; check it once with a push to `main` of a commit that is not checked out, which must be refused. It runs the version and deploy-pin checks (no pending re-pin), installs the tree for real with `tools/install-files.sh` into a temporary root, checks the installed admin page imports from that tree alone, and runs the bot Update and Set up scenarios in `tests/test_lifecycle_scenarios.py` against it. A scenario that can't run is a failure. How bot Update and Set up must behave, state by state, is in [docs/bot-lifecycle.md](docs/bot-lifecycle.md).

Before, a main bot one release behind with the same instructions apart from the release line counted as up to date, so its row had no Update button, and Set up on another bot failed with "couldn't pass it on" because the main bot checks this release's setup pins against the ones it holds. Now its row shows Update, the Bots page says to update it first, and Set up answers "Update the main bot first." until it has. Other bots keep the 0.12.10 rule: a release-line-only difference is not an update. New: [docs/bot-lifecycle.md](docs/bot-lifecycle.md) is the spec for bot Update and Set up, and `tools/release-check.sh` is the pre-push gate (see Releasing). The home helper stays 0.13.33. Press Update on the main bot first, then on the others.

### 0.13.34
The admin page answers again after an install or Update. The 0.13.33 installer left out `admin/gs_render.py`, which the admin page needs at start, so the page kept restarting and never answered. The installer now copies it, and a test fails whenever a module the admin page imports is not installed. Bot updates were not affected. A bot Update that gets no reply now ends on time on the Bots page, even while the page can't reach the station: after 10 minutes the row shows "Update failed: No reply within 10 minutes." and the Update button again, instead of "Updating…". The home helper stays 0.13.33. Press Update on each bot after installing.

### 0.13.33
Set up on a bot that is not connected yet is Confirm and send, then one yes in that bot's chat the first time. The bot fetches this release's routine from the pinned GitHub file, posts its public key and computer name, and sends two links for the webhook URL and webhook key. On the row, compare the key fingerprint with the one in the bot's chat and press Accept. Reject leaves the bot unpaired. Paste the webhook URL and key after that. The row is connected only then. The home helper is 0.13.33, so Update reinstalls it. Press Update on each bot after installing.

### 0.13.32
A bot update status line is no longer refused when a 16-hex id happens to contain a 9-digit run that looks like a Social Security number. Secret checks on that line still run, and a free-text answer with an SSN or card number is still blocked. The home helper stays 0.13.30. Press Update on each bot after installing.

### 0.13.31
A wake word that is not good enough now says which check failed, with the numbers. Recall short of 0.80 asks you to record 5 more clips, said clearly, somewhere quiet. Another sound that is too close asks for a longer or more distinct phrase, or a quieter room. Clear training and the next recording use the same clock, so those new clips are the ones that get scored. The home helper stays 0.13.30. Press Update on each bot after installing.

### 0.13.30
The Bots page can ask the main bot for the team list without speaking. Open More bot actions and choose Rescan bots. Names that are not on the station yet show up as Not set up, the same as saying "Hey Grok, update my team list." It does not change bots that are already set up. The page waits with the main bot (up to about 3 minutes) and says what happened. Set up a main bot first. Turning off Block personal info applies to the next reply. A bot update status line is not treated as personal info, so a computer named helper no longer leaves the update unfinished. A blocked private host name or household name is named on its own, and a secret is still blocked either way. The home helper is 0.13.30. Press Update on each bot after installing.

### 0.13.29
Home bots can post again after another Python on the same computer leaves bytecode caches in the helper's vendor folder. A `.pyc` file inside a `__pycache__` folder no longer makes every post print a bare `refused`, and the helper never loads one; any other extra or changed vendor file still refuses. A refused feed post or card now says why: content filter, too many posts, station busy, station could not show it, signature not accepted, request expired, already answered, or format not accepted. The home helper is release 0.13.29, so Update reinstalls it on each home computer. System, Password and security has a new Allowed networks setting: up to 4 private IPv4 networks (for example a VPN at `192.168.77.0/24`, each /16 to /32) that may open this page and post bot replies, besides this station's own network. It is empty by default, saving it always asks for the admin password, and each change is logged with the old and new list. Press Update on each bot after installing.

### 0.13.19 (in development)
Bot instruction templates are pure ASCII again (straight quotes; "your owner" written out instead of the `{owner}` token) so bots still on 0.13.17 can update. The template check is printable ASCII only.

### 0.13.18
Updates mirror email: the email name is the kind (18 characters), its lead sentence is the headline (60), and optional detail is at most 90 characters. The same bot and kind replaces the previous update, and that latest update stays until the bot replaces or clears it. Needs you is one pinned item per bot until explicitly cleared. No progress updates.

The `{owner}` token is filled from the station’s local sign-in name when rendering bot instructions; absent or unsafe names become “your owner”. Names are not stored in the shipped templates. Update payloads preserve signed ISO timestamps across the relay/station boundary; only station 400 and 413 responses map to schema errors; station 401, 403 and 404 remain 503 (unavailable).
